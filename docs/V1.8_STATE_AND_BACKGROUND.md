# Kinich 1.8.0 — Session State and Custom Background

**Baseline:** Kinich 1.7.2  
**Purpose:** specify and verify the two approved improvements before implementation.  
**Scope:** richer session-state expression; user-owned static background image with automatic accent-color derivation.

## Product constraints

- Keep the official DSH conversation, composer, controls, routes, and navigation in charge. Kinich only adds presentation.
- Preserve every existing Jungle, Ajaw, click, ambient, and immersive animation. Existing settings and reduced-motion behavior continue to work.
- Do not add third-party image assets, remote image fetching, voice/prompt injection, new theme families, Live2D, or a replacement chat UI in this update.
- Do not add animated, GIF, or video wallpaper in 1.8.0. Complex dynamic wallpaper remains a later, separately profiled project.
- Do not infer pending approval from button labels, DOM text, or `SessionSnapshot` fields that do not promise that meaning.
- Preserve the declared DSH compatibility range. If an optional newer status source is absent, keep existing state feedback working and omit only the new waiting state.

## A. Session-state expression

### Normalized states

The client uses one presentation vocabulary:

| State | Source | Presentation intent |
| --- | --- | --- |
| `idle` | No active or pending work | Existing calm Ajaw behavior |
| `sending` | An explicit pending submission / first-turn signal | Brief sending cue |
| `running` | The selected main Session reports running | Existing work animation |
| `waiting` | DSH's effective pending interaction for that same Session | Visible but restrained attention cue for approval, question, or plan review |
| `complete` | A previously active send/run returns to idle without an error or pending interaction | Existing short completion cue |
| `error` | A supported Session error field is present | Existing error cue |

### Data flow and priority

1. Keep `deriveKinichSessionPhase(snapshot)` pure for Session lifecycle facts.
2. Read pending user interaction from the root `useSessionStatus` projection when DSH supplies it. It is keyed by Session ID and carries `pendingInteraction`; the projection is the passive status source, not the `conversation.composer` takeover chain.
3. Resolve the main-view Session ID first, then read only that Session's pending interaction. A question or approval belonging to another open Session must not affect Ajaw.
4. Normalize only known interaction kinds (`approval`, `question`, `plan-review`) to `waiting`; unknown or absent values produce no waiting state.
5. Presentation priority is `error` → `waiting` → `sending` → `running` → `complete` → `idle`. A pending interaction therefore takes precedence over a concurrently true `running` value.
6. Entering `waiting` clears the “previous work completed” edge. If a request is rejected or cancelled and no work resumes, do not show a false completion celebration. If work resumes and later settles normally, the existing completion cue remains available.
7. Older DSH versions without the status projection continue through the current lifecycle logic; they do not guess at the new state.

### State feedback

- Reuse the existing Ajaw state shell, badge, and screen-reader live region; add a distinct waiting symbol/color and concise localized label.
- Keep waiting animation bounded and subdued. It must not override a low-balance alert's established base styling or block dragging, balance access, or DSH controls.
- Localize the state label and accessible description in English and Simplified Chinese.
- Clear pending presentation on Session change, interaction resolution, plugin disable, or unmount. Do not store pending interaction in Kinich settings.

## B. Custom background and automatic palette

### User flow

Add a “Custom background” control in the existing Kinich settings section:

1. The user selects one local PNG, JPEG, or WebP image.
2. The client validates and normalizes it before saving: reject files above 15 MiB, decode failures, zero dimensions, or source dimensions above 40 megapixels; downscale proportionally to at most 1920×1080; encode to WebP; reject the result if it still exceeds 512 KiB.
3. Show a preview and persist the optimized `data:image/webp;base64,...` value in the existing profile-backed Kinich settings namespace. The original file is never uploaded, stored in the plugin package, or sent to a model or remote service.
4. Automatic palette extraction chooses one dominant chromatic accent from a small downsampled pixel buffer. Ignore transparent, near-neutral, near-black, and near-white samples. Persist the resulting validated `#RRGGBB` accent alongside the background.
5. With “Automatically match accent” enabled (default), derive a light/dark accent pair from that color and overlay only Kinich-owned accent tokens. Keep the current Jungle surfaces and semantic success/warning/error colors intact. If extraction has no usable color, retain the current preset accent.
6. A reset action clears the image and extracted accent together, restoring the exact current preset appearance. A failed write keeps the previous saved image and uses the existing retry feedback.

### Persistence and safety

- Add `customBackgroundImage`, `customBackgroundAccent`, and `backgroundAutoPalette` to the shared setting definitions with backward-compatible defaults.
- Use the existing DSH-backed settings writer; do not persist the image in `localStorage` or IndexedDB, whose browser origin may vary across DSH profiles/restarts.
- Validate the optimized image data URL prefix, maximum encoded length, accent format, and toggle type in the shared decoder. A malformed new field falls back independently to its default without discarding valid pre-existing Kinich settings.
- Store no original filename, file path, EXIF metadata, or other file metadata. Canvas re-encoding removes source metadata.
- Render the image behind DSH content in a pointer-transparent decorative layer. Use a fixed contrast veil and bounded token transparency so text, the composer, menus, and focus indicators remain readable.
- When no custom background is selected, preserve the current CSS/token output byte-for-byte where practical.

### Palette derivation

- Implement color sampling as a pure, testable utility over a small RGBA pixel buffer; keep file decoding/canvas work in a browser-only helper.
- Derive only the accent family (brand, primary action, active/focus accent). Do not recolor errors, warnings, success, or neutral text roles.
- Generate separate light and dark accent values from the dominant hue, with luminance limits and WCAG contrast checks. If a generated value misses its role's contrast threshold, adjust lightness; if no safe value is found, use the preset accent.
- Apply the result as a plugin-owned `ctx.theme.overrideTokens` layer and dispose it cleanly when the image changes, the feature is reset, or the plugin unloads.

## Implementation order

1. Extend shared settings and backward-compatible decoding; add pure tests for state precedence, pending-interaction normalization, palette extraction, contrast, and invalid-field recovery.
2. Add the optional DSH session-status adapter with a tested fallback for older runtimes. Update the Ajaw state bridge and English/Chinese labels.
3. Add browser image validation/normalization, compact settings UI, safe persistence, and the background layer.
4. Derive and apply the accent token overlay; verify reset, failed-write retry, reduced motion, light/dark transitions, and theme-token disposal.
5. Build and run `npm run verify`, package dry-run, and isolated-profile install using the current Desktop runtime. Then launch a clean isolated DSH Desktop/Web session for visual review.

## Acceptance criteria

- All six normalized states have a deterministic unit test, including error priority, waiting over running, waiting cancellation with no false completion, and waiting → resumed run → complete.
- Pending interaction is matched by the currently selected main Session only. An absent optional DSH status source is harmless.
- Upload accepts the supported local image formats, outputs a valid bounded WebP, rejects oversize/corrupt input, and never performs a network request.
- Background and extracted accent survive profile restart; clear/reset restores the exact preset. Old settings without new fields still decode unchanged.
- Auto palette produces stable results for representative colorful, transparent, grayscale, and nearly black/white fixtures; generated accent contrast passes the defined checks in both light and dark modes.
- The image layer never captures input and does not obscure text, menus, composer controls, Ajaw, or keyboard focus. Existing animations and reduced-motion behavior remain unchanged.
- `npm run verify`, `npm pack --dry-run`, and an isolated DSH `0.2.0-rc.2` install pass. Real Windows Desktop visual acceptance is recorded separately from automated tests.
- No version is published by this implementation pass unless separately requested. Existing third-party asset distribution evidence remains a release consideration and is not replaced by this user-background feature.

## Out of scope for 1.8.0

Animated wallpapers, video, WebGL/Wallpaper Engine bridges, theme-pack import/export, new palette families, voice/prompt changes, Live2D, external companion processes, and broad layout redesign.
